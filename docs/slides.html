The Problem

Manual Process

  • Circuit schematics exist as images in textbooks, papers, handwritten notes
  • Recreating them in LTspice means manually placing every component and wire
  • Time-consuming and error-prone
  • No automated tool exists for this conversion

Our Solution

  • Upload a screenshot or photo
  • AI identifies components, values, and connections
  • Deterministic algorithms handle layout and wiring
  • Export a working .asc file for LTspice
  • Edit and refine in a visual editor

Pin Coordinate Transform

Pins in the .asy file use LTspice local coordinates. The SVG path is shifted so its bounding box starts at (0,0). We apply the same shift to pin positions:

// Voltage + pin: LTspice (0, 16)
// Bounds min: (-32, 16)

svg_x = 0 - (-32) = 32
svg_y = 16 - 16 = 0

// Pin appears at (32, 0) in SVG space
// = top-center of the circle

Validation: Find Open Pins

After Pass 1, we build a circuit graph and check: does every component pin connect to something?

def validate(self):
    unconnected = []
    for comp in self.components:
        for pin in comp.pins:
            if pin not in any_net:
                unconnected.append(pin)
    return {
        "all_connected": len(unconnected)==0,
        "unconnected_pins": unconnected
    }

Pass 2: AI Fixes the Gaps

If open pins are found, we send the image back to the VLM with explicit instructions:

Prompt to VLM (Pass 2):

  • These pins are NOT connected: R3.B, V2.+
  • Every pin must be connected
  • The circuit must be closed (complete current path)
  • Longer line = positive (+) terminal

Why This Matters

  • Open circuit = VLM missed a wire → Pass 2 fixes it
  • Wrong polarity = VLM can't tell +/- → explicit rules help
  • Result: all pins connected, correct orientation

Step 2: Net Building (Union-Find)

The Problem

The VLM gives us pairwise connections:

V1.+ ─> R1.A
R1.A ─> R2.A
R2.A ─> R3.A
R3.A ─> V2.-

But we need to know that all five pins are on the same net (electrically connected).

Union-Find

Merge connected pins into groups. If A connects to B and B connects to C, then A, B, C are all in one net.

Result

Pairwise connections: V1.+ ─ R1.A R1.A ─ R2.A R2.A ─ R3.A R3.A ─ V2.- ▼ Union-Find Net 0 (top bus): {V1.+, R1.A, R2.A, R3.A, V2.-} Net 1 (bottom bus): {V1.-, R1.B, R2.B, R3.B, V2.+}
def _uf_union(a, b):
    root_a = _uf_find(a)
    root_b = _uf_find(b)
    if root_a != root_b:
        parent[root_a] = root_b

Step 3: Orientation Resolution

Topology-Driven, Not VLM-Driven

The VLM often gets polarity wrong. Instead, we determine orientation from which nets each pin connects to.

  • R0 — Pin A's net is above pin B's net
  • R180 — Pin A's net is below (flipped)
  • R90 — Both pins on same-tier nets (horizontal)
if tier_a < tier_b:
    rotation = "R0"     # A on top
elif tier_a > tier_b:
    rotation = "R180"   # flipped
else:
    rotation = "R90"    # horizontal

Example: V2 gets R180

V1 (R0): + pin ──> top net (tier 0) - pin ──> bottom net (tier 1) tier 0 < tier 1 ──> R0 ✓ V2: - pin ──> top net (tier 0) + pin ──> bottom net (tier 1) tier 0 > tier 1 ──> R180 ✓ (+ is pin A, its net tier=1 > 0)
V1 [+] V2 [-] [─] ═══ top bus ═══ [─] [-] [+]

V2 is automatically flipped so its - pin faces the top bus.

Step 4: Wire Routing Algorithm

Direct Wires + Bus Strategy

For each net:

  1. Group pins by column (same X within 16px)
  2. Direct vertical wires within each column
  3. Horizontal bus connecting all columns
  4. One stub per column from closest pin to bus
# Columns for top net:
col_160: [V1.+, R1.A]  # 2 pins
col_576: [R2.A]         # 1 pin
col_992: [V2.-, R3.A]   # 2 pins

# Direct wires:
WIRE 160 256 160 512  # V1+ to R1.A
WIRE 992 256 992 512  # V2- to R3.A

# Bus + stubs:
WIRE 160 240 992 240  # bus
WIRE 160 256 160 240  # stub
WIRE 576 400 576 240  # stub

Visual Result

═════════ bus y=240 ═════════ | | | V1.+ R2.A V2.- | (direct) | V1.- V2.+ | (direct) | R1.A R3.A | | | R1.B R2.B R3.B | | | ═════════ bus y=608 ═════════

6 wires per net — clean, no overlaps, no wires through components.
